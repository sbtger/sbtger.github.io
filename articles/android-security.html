Android 的分层结构

层次职责
应用层应用提供界面和具体功能，通过框架 API 请求系统服务。
应用框架组织组件生命周期、窗口、资源和系统服务。
运行时与原生库运行时处理应用字节码，原生库提供图形、媒体与其他底层能力。APK 中的 DEX 文件承载字节码。
Linux 内核承担进程管理、内存、文件系统和设备驱动等工作。

组件与进程边界

Activity 提供界面，Service 提供可启动或绑定的服务，BroadcastReceiver 接收事件，ContentProvider 提供结构化数据接口。Service 默认也在应用的主线程运行，长时间任务仍需安排合适的执行环境。

应用沙箱与权限

系统通常为应用分配独立的 Linux UID，文件权限和进程隔离形成基本的应用沙箱。需要共享数据时，可以通过带权限控制的 ContentProvider 只开放必要的资源。普通权限、危险权限与签名权限的授予条件不同。危险权限的授权流程需要结合 Android 版本和应用目标版本理解。

Intent 与 WebView

Intent 可以跨应用携带数据，敏感值应仅传给预期接收方。PendingIntent 把一项未来可执行的操作交给其他组件，应限定操作范围。WebView 接收外部链接时，需要明确允许的来源、协议与本地文件访问范围。

审查应用

先阅读应用清单中的权限与组件声明，再核对实际使用的系统服务、进程间通信和数据共享接口。结合自有应用的运行日志检查敏感数据是否意外写入文件或日志。设备侧还要区分 USB 调试、蓝牙、Wi-Fi 与 NFC 各自的连接和授权边界。
